# Code walkthrough

Implementation baseline: `3193e84826dd3d01af1bf43295e11e7988acc605` (merged PR #5). This guide explains the maintained code, not future roadmap promises. Start with the [workbook](../guide/Playwright-Ecommerce-Quality-Framework-Guide.md), then rehearse with the [interview guide](interview-guide.md). The [PDF](../guide/Playwright-Ecommerce-Quality-Framework-Guide.pdf) is generated from the workbook.

## Execution map

```text
npm run validate
  doctor -> format -> lint -> typecheck
  -> run-tests -> denial preload -> deterministic config
     -> specs -> fixtures -> page objects / client -> assertions
     -> fixture audits -> list + HTML reports
  -> build support -> repository checks

Separately authorized live command
  run-live -> opt-in + outputs + arguments + local lock
  -> marker preload -> live config -> selected specs
  -> fixtures -> shared budget -> routed UI / fixed API requests
  -> sanitized errors + traffic -> HTML + summary -> unlock
```

These arrows represent control flow and composition, not a deployment. The repository contains no ecommerce application, backend or database. Dependencies flow from specs into fixtures and narrow abstractions; pure contracts do not import HTTP transport. Both configurations use Chromium, one worker and zero retries, but select disjoint test directories. A deterministic failure never falls back to live execution.

## Four end-to-end traces

### Deterministic UI: controlled catalog

1. `npm test` calls `scripts/run-tests.mjs`. It validates deterministic environment keys and artifact roots, restricts CLI arguments, and spawns Playwright with `deny-network.mjs` in `NODE_OPTIONS`.
2. The preload patches covered Node network primitives and sets the internal marker. `playwright.config.ts` checks that marker before test discovery. Workers inherit the preload.
3. `tests/deterministic/products.spec.ts` requests `catalog`. The automatic `networkGuard` fixture installs routes on the isolated context before the page fixture is used.
4. `ProductListPage.open()` navigates to the synthetic `https://fixture.invalid/products` identifier. `installNetworkGuard` fulfills exactly this GET navigation using `productDocument`; it makes no request to that host.
5. The spec checks one list item, the heading `Synthetic Blue Shirt`, and `Rs. 500`. Page-object methods supply locators; assertions belong to the spec.
6. Teardown calls the audit returned by the guard. Any unexpected request makes teardown fail even if the test caught its immediate error. Playwright closes the context and writes the deterministic report; synthetic failure capture is enabled.

### Deterministic API: controlled product list

The second scenario in the same spec requests `productApi`. The fixture constructs `ProductClient` with an async in-memory function returning HTTP-like status 200 and a fresh `buildProducts()` value. `list()` supplies the fixed `/api/productsList` path, converts transport exceptions to a safe `FrameworkError`, rejects a non-200 status, then calls `parseProducts`. Zod checks the body and returns consumed fields; the spec compares the exact synthetic product array. No HTTP request exists in this flow.

**Newly documented current limitation:** discovered during the study-guide review, not an accepted historical N-1–N-5 disposition. This is a potential future optimization; API requests themselves use no Playwright `page`, while shared automatic fixtures may still create a browser context. **Lifecycle detail:** the shared deterministic fixture has an automatic guard depending on `context`. Consequently this API scenario still creates a browser context, although its API operation uses no browser page. The live fixture has the same nuance through `audit`. Do not claim that these shared-fixture API suites require no browser process. Several pure boundary tests import base Playwright `test` and request no browser fixture.

### Live UI: quantity three

This is a code trace, not an instruction to execute live tests. With separate authorization and valid opt-in, the live wrapper creates its lock and launches the live config through the marker. `catalog.ui.spec.ts` requests `detail` and `cart`. They share the test's isolated page; automatic `audit` installs `installLiveNetwork` first.

`LiveProductDetailPage.addThree()` opens `/product_details/1`, fills the spinbutton with `3`, clicks Add to cart and waits for Continue Shopping. The browser is offline: allowed requests are fetched through `route.fetch`, counted and spaced through the shared `LiveBudget`, and fulfilled back to the browser. Unapproved traffic is aborted. `cart.open()` navigates to `/view_cart`; `checkRow` asserts Blue Top, price 500, quantity 3, total 1500, and displayed arithmetic. It does not test checkout, reload persistence or account state. The fixture audits routing, sanitizes errors and attaches cumulative numeric traffic. Context closure ends the session.

### Live API: unsupported method

`catalog.api.spec.ts` uses `api.send('unsupported')`. `LiveHttpTransport` selects POST `/api/productsList` from its fixed operation table; it accepts no arbitrary URL from the spec. The injected Playwright request context sends after `budget.dispatch()`, with 15-second timeout, no automatic redirects and no retries. Each accepted redirect consumes another dispatch and must preserve the endpoint with no query. The adapter disposes each response, parses bounded JSON and returns `{ status, body }`.

The spec expects **HTTP 200**, then uses `parseRejection` and asserts **provider responseCode 405** with its expected message. These are independent layers. The adapter does not itself call `ProductClient` or a domain schema; the live specs choose their parser. Its HTTP context is independent of page interaction, but the shared automatic audit still instantiates a browser context. Headed mode is forbidden for API selection.

## File-by-file reference

All paths below are relative to the repository root. Every maintained framework, test, script and configuration file is covered. Responsibilities include inputs, outputs, side effects and significant failure behavior; a pure module has no I/O unless noted.

### Configuration and pure data

| File                                | Responsibility, boundary and failure behavior                                                                                                                                                                                                                                   |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/config/runtime.ts`             | Takes an environment map; rejects unknown `QE_` keys and invalid deterministic settings through Zod. Returns a frozen mode/timeout/artifact-root object. No I/O; never echoes rejected values.                                                                                  |
| `src/config/live.ts`                | Parses exact live opt-in and approved base origin, checks raw URL authority, and answers browser method/resource/path/query policy questions. Returns frozen config, URL or boolean. Invalid config/URL throws safely; request predicate returns false. No requests occur here. |
| `src/config/errors.ts`              | Defines `FailureKind` and `FrameworkError(kind, message)`. Produces classified errors; callers must supply safe messages. It is not a universal automatic redactor.                                                                                                             |
| `src/config/deterministic-guard.ts` | Reads a process-local symbol and throws if the preload is absent. No transport or file I/O. Checked by config and deterministic fixture module.                                                                                                                                 |
| `src/config/output-paths.ts`        | Resolves only fixed `test-results`, `playwright-report`, or `dist` roots, rejects links/escapes including nested links, creates directories and probes writability. Throws configuration errors before tool cleanup.                                                            |
| `src/config/sanitize-failure.ts`    | Takes a mutable error object, classifies its message and removes stack/snippet/value/cause/errorContext. Mutates the object; keeps no raw diagnostic. Categories are triage hints, not proof of root cause.                                                                     |
| `src/data/products.ts`              | `buildProducts()` returns a fresh synthetic payload; `productDocument` is static hand-authored HTML. No transport and no captured provider data. Fresh arrays prevent mutation leaking between callers.                                                                         |

### Composition, routing and reporting

| File                             | Responsibility, boundary and failure behavior                                                                                                                                                                                                                                                                                                      |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/fixtures/deterministic.ts`  | Extends Playwright with automatic context guard, catalog and in-memory ProductClient fixtures; re-exports expect. `use` scopes lifecycle; teardown audits swallowed denials. Automatic context means API scenario setup is not wholly browser-free.                                                                                                |
| `src/fixtures/network-guard.ts`  | Installs context HTTP/WebSocket routes, fulfills one exact synthetic navigation, aborts others and returns a sticky audit assertion. No outbound fetch; any denied request is a teardown failure.                                                                                                                                                  |
| `src/fixtures/live.ts`           | Worker-scoped budget/cache plus per-test page objects, HTTP adapter and automatic context audit. Attaches cumulative traffic in finally and sanitizes errors. Playwright owns context/request disposal.                                                                                                                                            |
| `src/fixtures/live-budget.ts`    | Serializes dispatch admission with a promise queue: at most 100 sends, one-second spacing, five-minute elapsed limit. Tracks blocked/cache hits separately. `stop()` sets sticky failure; no request is sent by this class itself.                                                                                                                 |
| `src/fixtures/live-network.ts`   | Intercepts browser traffic, checks policy and redirects, fetches approved bytes, fulfills them, caches only 200 CSS/script bodies and content type. | `src/reporting/live-reporter.ts` | Receives Playwright events before list/HTML reporters, scrubs step/test/runner errors, clears stored stdout/stderr, keeps `traffic` attachments and writes `summary.json`. Trusted fixture supplies numeric traffic; reporter parses but does not schema-validate that attachment. It is not a general secrecy guarantee for arbitrary added code. |

## Headed execution and honest boundaries

After separate live authorization, `npm run test:live:ui:headed` selects UI and passes `--headed` through the protected wrapper. It changes browser visibility, not origins, budgets, sessions, retries or capture policy. `npm run test:live:api` uses the HTTP adapter; headed API is rejected. The deterministic wrapper supports Inspector through `npm run test:debug`, not arbitrary Playwright flags.

The live fixture's automatic context means API selection can still launch headless Chromium. Calling it “browser-free” would conflate request transport with fixture lifecycle. Removing that overhead would require a separately authorized fixture change; this documentation task changes no framework behavior.

Further limits: network guards protect maintained code against accidents, not hostile code; sizes are checked after buffering; browser and API redirect handling differ on 303; reporter sanitization is intentionally coarse; local and CI locks are not distributed. Consult the [recorded non-blocking findings](roadmap.md) before presenting any of these as resolved.
